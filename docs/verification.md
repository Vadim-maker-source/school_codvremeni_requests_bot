# Проверки текущей версии

## Автоматические проверки

- Backend: 63 passed. 37 существующих тестов + 26 Telegram-тестов. Все работают на отдельных временных SQLite, не отправляют сообщения в Telegram.
- Aiogram Dispatcher: реальные маршруты message/callback_query с fake transport; полный диалог, повтор подтверждения, сохранение состояния, доступ к статусу только владельцу.
- Telegram: одноразовая привязка с авторизацией/CSRF, срок 10 минут, уникальность ID, отвязка; очередь администратора/работника/заявителя; отмена отправки отвязанному/неактивному сотруднику; аренда, временные/постоянные ошибки.
- Playwright: вход, получение Telegram-ссылки в кабинете, категории, полный цикл заявки, сотрудники, статистика, фильтры, мобильный экран 375px, фокус и reduced motion. Runtime ошибок нет.
- Production Next.js build и TypeScript прошли; pip check — No broken requirements found.

## Локальный запуск

На этом компьютере применена миграция PostgreSQL, Alembic check — No new upgrade operations detected. API и веб-сборка отвечают; health показывает database=ok, bot=running, notifications=running. Telegram getMe подтвердил аккаунт, aiogram запустил polling и обрабатывает входящие обновления.

Обычные скрипты запуска/остановки учитывают отдельный процесс бота, секрет хранится в исключённой локальной конфигурации.

## Что ещё проверить вручную

В рабочей очереди проверены 3 отправленных сообщения: Telegram принял их, максимальная задержка от создания задания до подтверждения — 2,57 секунды; ошибок и ожидающих сообщений не было. Telegram привязан у администратора, у двух операторов привязки нет. Матрица ролей проверена fake transport; реальную доставку операторам нужно подтвердить после их привязки. Подтверждение Telegram API не доказывает прочтение пользователем.

Расчёт производительности в performance.md относится к прежнему ноутбуку с SQLite. На PostgreSQL этого компьютера нагрузочный тест пока не выполнен. Docker и production hosting не проверялись.

У тестового стека остаётся предупреждение Starlette об HTTPX; тесты проходят.

Проверены и исправлены: одно сообщение на событие при совмещении ролей заявителя и администратора; отменённые задания больше не останавливают обработку следующих записей. Проверены несколько администраторов, смена роли, деактивация/отвязка/перепривязка, устаревшее назначение, веб- и Telegram-заявки, выполнение и отклонение.
