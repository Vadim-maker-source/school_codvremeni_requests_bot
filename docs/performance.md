# Локальное измерение производительности

Команда из корня проекта:

```powershell
backend/.venv/Scripts/python.exe backend/tests/test_http_instance.py --seconds 15 --clients 4 --output work/performance.json
```

Скрипт создаёт временную SQLite, применяет миграции, инициализирует тестовые учётные записи, запускает отдельный FastAPI на свободном loopback-порту, выполняет полный HTTP-сценарий, измерение, затем завершает только своё дерево процессов и удаляет временные данные. Рабочая `backend/data/requests.db` не используется. Telegram не вызывается. Если выполнить с `--seconds 3600`, получится отдельное часовое испытание; сегодня оно не проводилось.

## Условия фактического запуска

- Дата: 5 ноября 2026, 14:12 по Москве (`2026-11-05T11:12:42Z` — начало отчёта).
- Windows 11, сборка 26200, Intel Core i5-11400H 2.70 GHz, 6 ядер / 12 потоков, около 15.7 GiB RAM.
- Python 3.12.5, SQLAlchemy 2.0.57, FastAPI 0.162.0, один uvicorn worker.
- SQLite, временный локальный файл, WAL, foreign_keys, busy timeout 15 с. PostgreSQL не запускался.
- 4 параллельных клиента HTTPX с keep-alive, 15.030 с фактической измеренной работы, без искусственной паузы между циклами.
- Цикл: создать заявку → прочитать первую страницу списка из 15 строк → взять созданную заявку в работу. Авторизация выполнялась до таймера. Полное закрытие с переназначением проверялось отдельным smoke-сценарием, не входило в измеряемый цикл.
- Это разработческий ноутбук с другими локальными процессами. На фоне измерения выполнялись backend-тесты и проверки зависимостей, поэтому результат не является изолированным аппаратным максимумом.

## Результат

| Операция | Попыток / успешных | Ошибки | Среднее, мс | p95, мс | Успешных операций/с |
|---|---:|---:|---:|---:|---:|
| Создание | 787 / 787 | 0% | 24.36 | 51.69 | 52.36 |
| Список | 787 / 787 | 0% | 25.57 | 42.67 | 52.36 |
| Новая → В работе | 787 / 787 | 0% | 26.36 | 57.79 | 52.36 |

787 полных измеряемых циклов, всего 2 361 успешная операция. Фактическая скорость — 52.36 цикла/с. Пересчёт по неокруглённой скорости даёт **188 505 заявок/час — экстраполяция короткого 15-секундного теста**, в котором каждая заявка создавалась, читалась и бралась в работу. Это не доказательство часовой стабильности, не производительность людей и не скорость полного цикла с закрытием.

Среднее и p95 вычисляются отдельно для каждого вида операции; p95 — ближайший ранг в отсортированных измерениях. Скорость успешных операций делится на общую фактическую длительность теста. Учитываются неуспешные HTTP-коды и сетевые ошибки; в этом запуске их не было. Полный машинный отчёт: `docs/performance-results.json`.

## Ограничения

Маленькая растущая база (одна smoke-заявка плюс 787 нагрузочных), локальная сеть, отсутствие реальных Telegram-уведомлений и фонового отправителя. Лимит входа повышен **только** в тестовом процессе, чтобы запуск клиентов не искажал нагрузку; рабочая конфигурация остаётся 10 / 300 с. Долгие транзакции, большие исторические базы, многопроцессный сервер, удалённый диск и реальные пользователи здесь не моделировались. SQLite имеет ограничения одновременной записи. Эти числа нельзя переносить на PostgreSQL; для него нужен самостоятельный стенд, миграции, проверка сценария и измерение.
