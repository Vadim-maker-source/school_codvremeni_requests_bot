# Telegram-бот

Реализован на aiogram 3.31, long polling. Бот, веб-API и очередь используют общую PostgreSQL и ticket_service.

## Привязка сотрудника

1. Войти в кабинет под своей учётной записью.
2. Нажать колокольчик → «Получить ссылку привязки».
3. Открыть ссылку в Telegram и нажать «Начать».

Ссылка действует 10 минут, хранится только её SHA-256, используется один раз. Telegram ID берётся из доверенного Update. Один Telegram связан с одной учётной записью. У каждого администратора/оператора своя привязка; есть «Отключить Telegram» в кабинете. Деактивированные сотрудники уведомлений не получают.

## Диалог

/new: группа → элемент → описание → подтверждение. Есть «Назад»/«Отмена», валидация и проверка активных категорий. Имя заявителя — имя его профиля Telegram. ID и username автоматически берутся из Update при подтверждении, сохраняются вместе с заявкой, показываются в карточке и уведомлениях сотрудникам. Username может отсутствовать; ID остаётся идентификатором владельца. Бот работает в личном чате. Контакт заполняется автоматически: @username или Telegram ID; отдельного запроса контакта нет.

После подтверждения бот выдаёт номер. /mine показывает последние 10 своих заявок, /status проверяет полный номер только среди заявок текущего пользователя. /assigned показывает последние 10 открытых заданий связанного сотрудника. /id показывает собственный ID, но не связывает аккаунт.

Диалог хранится в telegram_dialogs и продолжается после перезапуска. telegram_submissions защищает подтверждение от повторной записи заявки; устаревшие кнопки не изменяют новый диалог.

## Уведомления

- Новая заявка с сайта или бота → активные связанные администраторы.
- Назначение/переназначение → связанный назначенный сотрудник.
- Взятие в работу → заявитель, связанный сотрудник и связанные активные администраторы.
- Выполнение/отклонение → заявитель и связанные активные администраторы, с результатом или причиной.

Outbox записывается в одной транзакции с событием. Worker проверяет очередь каждые 3 секунды, захватывает записи с двухминутной арендой. Перед отправкой сотруднику проверяет активность, текущую привязку и назначение/роль администратора. Временные ошибки повторяются до 5 неудач, затем failed; блокировка бота и неверный адрес — постоянные ошибки. Возможен повтор после аварии между отправкой и commit. Реальная задержка зависит от сети, Telegram и rate limit.

## Запуск и проверки

В backend/.env: TELEGRAM_BOT_TOKEN, TELEGRAM_BOT_USERNAME, NOTIFICATIONS_ENABLED=true. Секрет исключён из Git.

scripts/start-local.ps1 запускает API, сайт и один процесс бота; scripts/stop-local.ps1 останавливает их. Ручной запуск из backend: .venv/Scripts/python.exe -m app.bot. Не запускайте второй polling того же токена. /api/health показывает heartbeat бота и очереди. Логи — .local/bot-error.log; ошибки доставки хранят только имя типа исключения.

backend/tests/test_telegram.py проверяет Dispatcher aiogram через fake transport, сохранение диалога, назад/отмену, владение заявкой, повторы подтверждения, привязку/срок/уникальность/CSRF, маршрутизацию уведомлений, отвязку/деактивацию, аренду и ошибки. Браузерный сценарий проверяет получение ссылки привязки.

Для реальной приёмки: подключить администратора и оператора; подать заявку в боте; проверить номер на сайте и сообщение администратору; назначить оператору и проверить его уведомление; взять/закрыть и проверить статусы у заявителя. Fake transport не доказывает внешнюю доставку.

При совмещении ролей один Telegram получает одно сообщение на событие с более подробной информацией. Если рабочая роль/привязка утрачена, сохраняется только уведомление о собственной заявке. Отменённые записи пропускаются в том же проходе очереди.
