# Демонстрация готового веб-кабинета

Рабочая база изначально пустая. Выполните сценарий вручную с реальным обращением или запустите изолированный браузерный тест — он не добавляет данные в рабочую БД.

1. Войти оператором по локальным данным из `backend/data/local_credentials.json`.
2. Создать «Не работает проектор»: указать заявителя, контакт, «Оборудование» → «Проектор» и кабинет.
3. Показать выданный номер и карточку.
4. Закрыть карточку, найти номер в списке, продемонстрировать фильтр.
5. Открыть карточку и нажать «Взять в работу».
6. Выбрать другого активного оператора и переназначить.
7. Показать историю и смену исполнителя.
8. Нажать «Выполнить», написать «Заменён кабель HDMI, проектор проверен», подтвердить.
9. Показать счётчик выполненных. Подробная статистика доступна администратору.
10. Выйти, войти администратором, открыть статистику, сотрудников и классификаторы; показать создание, редактирование и деактивацию.

Автоматически проверяется аналогичный путь: `backend/.venv/Scripts/python.exe backend/tests/run_browser.py`. Тест использует отдельные SQLite, API, frontend и тестовые учётные данные. Отчёт — `work/browser/report.json`.

## Полный сценарий Telegram

1. Администратор и оператор каждый связывают свой Telegram через колокольчик в кабинете.
2. Заявитель открывает бота → «Создать заявку», проходит выбор группы/элемента, вводит описание; Telegram ID и username подставляются автоматически, затем подтверждает.
3. Бот выдаёт номер; администратор получает сообщение о новой заявке, та же заявка видна на сайте.
4. Администратор назначает оператора → оператор получает задание в боте.
5. Оператор берёт заявку в работу и закрывает с результатом → заявителю приходят статусы и результат.
6. Заявитель проверяет номер через /status; другой Telegram-аккаунт не получает доступ.

Реальный сценарий проверяется после привязки собственных аккаунтов; тесты с fake transport не доказывают внешнюю доставку.
